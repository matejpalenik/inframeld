# Projects, people and permissions

A Project groups related resources and access decisions. For example, the Support Project can hold a team's handbook and Pipelines while another Project remains private to its owner.

## Identity and names

The Project ID is permanent. Its name is an exact selector, such as `support`. Its display name is the label people see, such as **Customer Support**. Renaming a Project preserves its ID.

## Membership and permission

Authentication identifies a person. Admission permits product use. Project membership and specific action grants control what that person can inspect or change. Installation administration supplies no general document-reading bypass.

A currently authorized human can [admit an existing Kratos identity](/guides/admit-human) using the Organization's `admit-users` action. This links the person to local admission without granting Project membership, action permissions or private starters. It neither registers a provider account nor replaces the separate first-administrator host claim. An admission receipt describes its original result, not current authority. Private-starter provisioning and complete first-use readiness remain unfinished.

Changing permissions can affect the information returned by a later read. Historical records do not restore removed authority.

An eligible human with permission to use `manage-project-members` can [list a Project's stored memberships](/guides/list-project-members). A listed person or application account can be inactive. Membership is a relationship, not proof of current eligibility or a report of its action grants. The read does not add or remove members.

The same current human use authority can [add or remove an admitted human](/guides/manage-project-members). Joining gives bare membership. Departure clears that recipient's received action grants and group relationships within the Project, while preserving other recipients' grants and Project-owned resources. Removal must retain the required eligible human grantors and group managers. It never appoints a replacement automatically, and a later rejoin restores none of the removed access. An original receipt describes that operation rather than today's membership.

## Work with Projects

Use the HTTP API or a generated SDK to [create an additional Project](/guides/create-project) with creator membership and eighteen explicit, removable permissions on that Project. The API can also [read and change metadata](/guides/name-and-rename-project), resolve an exact name, and assign the supported use-only grant. See [Projects and access](/api-reference/projects-and-access) for the delivered contracts. Private-starter provisioning remains unfinished. The complete supported account-to-API procedure and human acceptance remain unfinished under [qualification #313](https://github.com/matejpalenik/inframeld/issues/313).
