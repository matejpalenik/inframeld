# Pipelines and builds

A Pipeline combines the knowledge, retrieval settings and model roles used to answer a question. Working configuration supports development. A build captures inputs and prepares a version that can be evaluated or considered for release.

## Develop without rewriting history

You can change working configuration while an admitted query keeps the inputs it captured. This lets you investigate a result against its original context instead of today's settings.

## Readiness and publication

A ready version has completed its required preparation and verification. Publication is a separate decision owned by the Deployment's release policy and current permission. A failed build does not replace healthy current traffic.

## Inspect an answer

Answer records can identify the version and evidence used, including meaningful evidence that was not cited in the final text. Keep this context when comparing quality or investigating a result.

Public Pipeline/query/build operations remain in development. See [configure pipelines and ask questions](/guides/pipelines-and-questions), [evaluation](/product/evaluation), and [releases](/product/deployments-and-releases).
