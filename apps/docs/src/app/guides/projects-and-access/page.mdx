## Understand access before changing it

Project names are exact selectors. IDs are permanent. Display names are labels. Read [Projects, people and permissions](/product/projects-and-permissions) for the distinction between sign-in, membership and action grants.

Human admission uses current Organization `admit-users` authority and verifies the requested Kratos identity. It creates no Project membership, grants or starters. It is separate from first-administrator bootstrap and provider account registration.

Membership changes use current Project `manage-project-members` authority. Adding an admitted human gives bare membership. Removal clears only that recipient's received access within the Project and preserves required human responsibilities. Rejoining restores no old grants or group roles. [The guide](/guides/manage-project-members) explains the current inputs, departure guards and original receipts.

[Project action-grant reads](/guides/list-project-action-grants) require current use and grant authority for the exact action on the Project. They list stored assignments, including suspended recipients, rather than effective permissions or every action the recipient may use. Your own-access read needs current eligible-human membership and returns a current Access revision, not a permission snapshot. Project grant PUT/DELETE require exact use-and-grant authority again, preserve original results and prevent removal of the last eligible exact-action grantor. `canGrant: false` means use-only, not removal. Other-resource and Organization grant administration remains separate work.

Project creation uses your current Organization `create-projects` permission. It creates an ordinary Project with its membership and eighteen initial assignments. Group administration and private-starter provisioning remain separate unfinished procedures. The [API reference](/api-reference/projects-and-access) lists the operations you can call today.

Application-account creation gives an integration its own permanent identity in one Project. It starts without received action grants, document groups or keys. Its creator receives three exact account-administration grants. [The guide](/guides/application-accounts) explains creation, current metadata visibility, safe key reads and recovery after response loss. Issuing or using application credentials and retiring an account remain separate unfinished operations.
