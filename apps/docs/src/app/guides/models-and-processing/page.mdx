# Configure models and processing

Create a model connection to save where a Project can reach a provider. You can inspect the saved configuration and grant someone permission to use the connection. Setup creates no provider key and makes no model request.

## Prepare the Project and destination

You need a current human credential, membership in the Project, and permission to use its `create-model-connections` action. Use the Project's permanent ID. Follow [HTTP setup](/clients/http#call-protected-operations) for `INFRAMELD_URL` and `INFRAMELD_TOKEN`. Set `PROJECT_ID` to the actual UUID and choose a `CONNECTION_CREATE_KEY` once for this request.

Ask your installation operator for the exact approved base URL and the supported provider settings. [Approved model destinations](/self-hosting/security#approve-model-destinations) explains the deployment allowlist and local Ollama exception.

Save this request as `model-connection.json`. The example uses an OpenAI-compatible gateway. Replace its base URL with the exact approved URL before sending.

<CodeGroup>

```json
{
  "name": "company-gateway",
  "displayName": "Company gateway",
  "access": {
    "provider": "openai-compatible",
    "baseUrl": "https://models.example.test/v1",
    "apiVersion": null,
    "authentication": "api-key"
  }
}
```

</CodeGroup>

Choose a Name of 1 to 63 characters. Use an ASCII lowercase letter first, then lowercase letters, digits and hyphens, ending with a letter or digit. Use a display name of 1 to 128 characters. The Name is unique within the Project. Keep the returned connection ID for later requests. `apiVersion` is required and currently takes `null`. `authentication: "api-key"` selects the authentication method. Supply no credential value in this request.

## Create the connection

Choose one alternative. For SDKs, follow the source-package setup for [Python](/clients/python#install-from-a-checkout), [TypeScript](/clients/typescript#build-and-install-the-package) or [Rust](/clients/rust#set-up-an-example-project). Save the complete program beside `model-connection.json` as `create_connection.py`, `create-connection.ts` or `src/main.rs` in the Rust example project, and run it from the directory containing the JSON file.

<CodeGroup>

```shell {{ title: "cURL" }}
curl --fail-with-body --silent --show-error --max-time 5 \
  --url "$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections" \
  --header @- \
  --header "Idempotency-Key: $CONNECTION_CREATE_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary @model-connection.json <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

```python
import asyncio
import os
from pathlib import Path
from uuid import UUID

import httpx
from inframeld_sdk import ApiClient, Configuration
from inframeld_sdk.api.access_api import AccessApi
from inframeld_sdk.exceptions import ApiException
from inframeld_sdk.models.model_connection_creation_request import (
    ModelConnectionCreationRequest,
)


async def main() -> None:
    request = ModelConnectionCreationRequest.model_validate_json(
        Path("model-connection.json").read_text(encoding="utf-8")
    )
    configuration = Configuration(
        host=os.environ["INFRAMELD_URL"],
        access_token=os.environ["INFRAMELD_TOKEN"],
    )
    async with ApiClient(configuration) as client:
        try:
            receipt = await AccessApi(client).create_model_connection(
                project_id=UUID(os.environ["PROJECT_ID"]),
                idempotency_key=os.environ["CONNECTION_CREATE_KEY"],
                model_connection_creation_request=request,
                _request_timeout=5.0,
            )
        except ApiException as error:
            print(f"No usable receipt. HTTP {error.status}. Keep the original request and key.")
            raise SystemExit(1) from None
        except httpx.HTTPError:
            print("No usable response. Keep the original request and key.")
            raise SystemExit(1) from None
    print(receipt.to_json())


if __name__ == "__main__":
    asyncio.run(main())
```

```typescript
import { readFileSync } from "node:fs"
import {
  createClient,
  createModelConnection,
  type ModelConnectionCreationRequest,
} from "@inframeld/sdk"

const baseUrl = process.env.INFRAMELD_URL
const token = process.env.INFRAMELD_TOKEN
const projectId = process.env.PROJECT_ID
const key = process.env.CONNECTION_CREATE_KEY
if (!baseUrl || !token || !projectId || !key) {
  throw new Error(
    "Set INFRAMELD_URL, INFRAMELD_TOKEN, PROJECT_ID and CONNECTION_CREATE_KEY"
  )
}

const body: ModelConnectionCreationRequest = JSON.parse(
  readFileSync("model-connection.json", "utf8")
)
const result = await createModelConnection({
  client: createClient({ baseUrl, timeoutMs: 5000 }),
  path: { project_id: projectId },
  body,
  headers: { Authorization: "Bearer " + token, "Idempotency-Key": key },
  responseStyle: "fields",
  throwOnError: false,
})

if (result.error || !result.data) {
  console.error(
    "No usable receipt. Keep the original request and key.",
    result.response?.status
  )
  process.exitCode = 1
} else {
  console.log(JSON.stringify(result.data, null, 2))
}
```

```rust
use inframeld_sdk::{HttpClient, ModelConnectionCreationRequest};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let request: ModelConnectionCreationRequest =
        serde_json::from_str(&std::fs::read_to_string("model-connection.json")?)?;
    let token = std::env::var("INFRAMELD_TOKEN")?;
    let client = HttpClient::new()
        .with_base_url(std::env::var("INFRAMELD_URL")?)
        .with_header("Authorization", format!("Bearer {token}"));
    match client
        .create_model_connection(
            std::env::var("PROJECT_ID")?,
            std::env::var("CONNECTION_CREATE_KEY")?,
            request,
        )
        .await
    {
        Ok(response) => {
            println!("{}", serde_json::to_string_pretty(&response.body)?);
            Ok(())
        }
        Err(_) => Err("No usable receipt. Keep the original request and key.".into()),
    }
}
```

</CodeGroup>

Run `.venv/bin/python create_connection.py`, `node create-connection.ts` with Node 26 in the TypeScript example project, or `cargo run` in the Rust example project.

A successful `201` returns the permanent `connection.modelConnectionId`, the original operation ID and expiry, the resulting Project Access revision, and four original creator grants. Each initial grant has `canGrant: true` for its exact action on this connection. [Model connection grants](/guides/manage-action-grants#grant-use-of-a-model-connection) lists the actions and the recipients you can choose.

## Check current settings and recorded use

Set `MODEL_CONNECTION_ID` to the returned ID. If you only have the Project ID, list the connections you can inspect by sending GET to the same Project collection URL used for creation. With a current `view-model-connection-configuration` grant, read that connection:

<CodeGroup>

```shell {{ title: "cURL" }}
curl --fail-with-body --silent --show-error --max-time 5 \
  --header @- \
  "$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections/$MODEL_CONNECTION_ID" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

The response reports the saved base URL, selected authentication method and connection settings revision. The `credential` summary shows the current presence and revision. A new connection starts with `credential.present: false` and revision `0`. The [API reference](/api-reference/projects-and-access#list-model-connections) shows how to continue a connection list.

Use the [usage read](/api-reference/projects-and-access#list-model-connection-usage) to inspect permitted saved observations. Append `/usage` to the connection URL and send the same authenticated GET. In this version the page has empty `items` and `nextCursor: null`. An empty page means there are no recorded observations to show. It gives no provider reachability or validation result. [Models, processing and search](/product/models-and-search) explains where consumer model and role settings belong.

## Recover an uncertain creation

Keep the original installation, Project, method, route, request body and key. A timeout, disconnect or unusable response can occur after creation. Within the retained period, explicitly repeat the original POST with those inputs and a current credential for the same human. Current `create-model-connections` authority still applies. The receipt describes the original connection and creator assignments. Later changes stay in force. Use GET for current configuration.

If a fresh request rejects the destination, ask the operator to confirm the exact URL and provider selection. Keep the original request separate if you have already sent it and its result is uncertain. Use a new key only for a deliberately changed, reviewed request.

## Save a provider credential

Save the API key for an existing `api-key` connection. The server stores the key without contacting the provider. Use a disposable Project and synthetic token when practicing this procedure.

You need the permanent `PROJECT_ID` and `MODEL_CONNECTION_ID`, a current human bearer credential and `manage-model-connection` on the exact connection. Use your installation's HTTPS URL and the [HTTP setup](/clients/http#call-protected-operations) for `INFRAMELD_URL` and `INFRAMELD_TOKEN`. The ordinary configuration read shows a credential summary under `view-model-connection-configuration`. The dedicated credential read and changes use `manage-model-connection`.

<CodeGroup>

```shell
CREDENTIAL_URL="$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections/$MODEL_CONNECTION_ID/credential"

curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --header @- "$CREDENTIAL_URL" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

Read `present` and `revision` in the response. Before the first save, the revision is `0` and `credentialId` and `changedAt` are `null`. Use the revision you read when preparing a save or replacement. [Credential metadata schema](/api-reference/models#ModelConnectionCredentialDetailsResponse).

Create a private request file outside your checkout and choose an idempotency key to identify this save request.

<CodeGroup>

```shell
CREDENTIAL_REQUEST_DIR=$(mktemp -d "${TMPDIR:-/tmp}/inframeld-credential.XXXXXXXX") &&
  CREDENTIAL_REQUEST_FILE="$CREDENTIAL_REQUEST_DIR/credential-save.json" &&
  (umask 077; : > "$CREDENTIAL_REQUEST_FILE") &&
  CREDENTIAL_SAVE_KEY=$(uuidgen)
```

</CodeGroup>

Use a protected local editor or secret-handling tool to prepare `credential-save.json`. Set `expectedCredentialRevision` to the revision you just read as a JSON integer. Set `value` to the raw provider token as a JSON string and omit the `Bearer` prefix. Keep the provider token out of shell arguments, environment variables and logs. Keep shell and HTTP tracing disabled. [Save request schema](/api-reference/models#ModelConnectionCredentialRequest).

<CodeGroup>

```shell
curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --request PUT --header @- \
  --header "Idempotency-Key: $CREDENTIAL_SAVE_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary "@$CREDENTIAL_REQUEST_FILE" "$CREDENTIAL_URL" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

HTTP `200` returns the resulting `credential.revision` and `credential.present`. The receipt's `changed` field records whether the original request changed the slot. To replace a saved key, read the current revision and prepare a separate protected file and idempotency key.

## Recover a save or removal after a lost reply

A timeout or disconnect can happen after the change commits. Keep the original installation, IDs, method, revision and idempotency key. For a save, keep the original JSON file protected as well. Within the retained result period, repeat the original call with a current credential for the same human. Keep the request inputs and key unchanged. Current management permission still applies.

An authorized replay returns the original `credential`, `changed`, `operationId` and `idempotencyExpiresAt` with `replayed: true`. Use GET to find today's state. A different secret under the same idempotency key conflicts. If retention may have expired, inspect current state before deciding whether to send a new request. Once the result is resolved, remove the protected local request file and its directory.

## Remove the saved provider credential

Check the current credential revision again and review any work you know depends on this connection. The current usage page only reports saved observations. An empty page cannot establish that removal has no impact. Future calls that require the key will need a saved credential. Already sent requests may finish. Revoke the provider's own key separately at the provider if needed.

Set `CURRENT_CREDENTIAL_REVISION` to the revision you just read. Run `CREDENTIAL_REMOVE_KEY=$(uuidgen)` once for this removal and keep both values in case the reply is lost.

<CodeGroup>

```shell
curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --request DELETE --header @- \
  --header "Idempotency-Key: $CREDENTIAL_REMOVE_KEY" \
  "$CREDENTIAL_URL?expectedCredentialRevision=$CURRENT_CREDENTIAL_REVISION" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

HTTP `200` returns the original removal outcome. Removing a present credential advances its revision and returns `credential.present: false`. A removal of an already empty slot at its current revision records `changed: false`. For a lost reply, reuse the original DELETE key and revision. [Recover a save or removal after a lost reply](#recover-a-save-or-removal-after-a-lost-reply).
