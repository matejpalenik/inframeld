# Configure models and processing

Create a model connection to save where a Project can reach a provider. You can inspect the saved configuration and grant someone permission to use the connection. Setup creates no provider key and makes no model request.

## Prepare the Project and destination

You need a current human credential, membership in the Project, and permission to use its `create-model-connections` action. Use the Project's permanent ID. Follow [HTTP setup](/clients/http#call-protected-operations) for `INFRAMELD_URL` and `INFRAMELD_TOKEN`. Set `PROJECT_ID` to the actual UUID and choose a `CONNECTION_CREATE_KEY` once for this request.

Ask your installation operator for the exact approved base URL and the supported provider settings. [Approved model destinations](/self-hosting/security#approve-model-destinations) explains the deployment allowlist and local Ollama exception.

Save this request as `model-connection.json`. The example uses an OpenAI-compatible gateway. Replace its base URL with the exact approved URL before sending.

<CodeGroup>

```json
{
  "name": "company-gateway",
  "displayName": "Company gateway",
  "access": {
    "provider": "openai-compatible",
    "baseUrl": "https://models.example.test/v1",
    "apiVersion": null,
    "authentication": "api-key"
  }
}
```

</CodeGroup>

Choose a Name of 1 to 63 characters. Use an ASCII lowercase letter first, then lowercase letters, digits and hyphens, ending with a letter or digit. Use a display name of 1 to 128 characters. The Name is unique within the Project. Keep the returned connection ID for later requests. `apiVersion` is required and currently takes `null`. `authentication: "api-key"` selects the authentication method. Supply no credential value in this request.

## Create the connection

Choose one alternative. For SDKs, follow the source-package setup for [Python](/clients/python#install-from-a-checkout), [TypeScript](/clients/typescript#build-and-install-the-package) or [Rust](/clients/rust#set-up-an-example-project). Save the complete program beside `model-connection.json` as `create_connection.py`, `create-connection.ts` or `src/main.rs` in the Rust example project, and run it from the directory containing the JSON file.

<CodeGroup>

```shell {{ title: "cURL" }}
curl --fail-with-body --silent --show-error --max-time 5 \
  --url "$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections" \
  --header @- \
  --header "Idempotency-Key: $CONNECTION_CREATE_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary @model-connection.json <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

```python
import asyncio
import os
from pathlib import Path
from uuid import UUID

import httpx
from inframeld_sdk import ApiClient, Configuration
from inframeld_sdk.api.access_api import AccessApi
from inframeld_sdk.exceptions import ApiException
from inframeld_sdk.models.model_connection_creation_request import (
    ModelConnectionCreationRequest,
)


async def main() -> None:
    request = ModelConnectionCreationRequest.model_validate_json(
        Path("model-connection.json").read_text(encoding="utf-8")
    )
    configuration = Configuration(
        host=os.environ["INFRAMELD_URL"],
        access_token=os.environ["INFRAMELD_TOKEN"],
    )
    async with ApiClient(configuration) as client:
        try:
            receipt = await AccessApi(client).create_model_connection(
                project_id=UUID(os.environ["PROJECT_ID"]),
                idempotency_key=os.environ["CONNECTION_CREATE_KEY"],
                model_connection_creation_request=request,
                _request_timeout=5.0,
            )
        except ApiException as error:
            print(f"No usable receipt. HTTP {error.status}. Keep the original request and key.")
            raise SystemExit(1) from None
        except httpx.HTTPError:
            print("No usable response. Keep the original request and key.")
            raise SystemExit(1) from None
    print(receipt.to_json())


if __name__ == "__main__":
    asyncio.run(main())
```

```typescript
import { readFileSync } from "node:fs"
import {
  createClient,
  createModelConnection,
  type ModelConnectionCreationRequest,
} from "@inframeld/sdk"

const baseUrl = process.env.INFRAMELD_URL
const token = process.env.INFRAMELD_TOKEN
const projectId = process.env.PROJECT_ID
const key = process.env.CONNECTION_CREATE_KEY
if (!baseUrl || !token || !projectId || !key) {
  throw new Error(
    "Set INFRAMELD_URL, INFRAMELD_TOKEN, PROJECT_ID and CONNECTION_CREATE_KEY"
  )
}

const body: ModelConnectionCreationRequest = JSON.parse(
  readFileSync("model-connection.json", "utf8")
)
const result = await createModelConnection({
  client: createClient({ baseUrl, timeoutMs: 5000 }),
  path: { project_id: projectId },
  body,
  headers: { Authorization: "Bearer " + token, "Idempotency-Key": key },
  responseStyle: "fields",
  throwOnError: false,
})

if (result.error || !result.data) {
  console.error(
    "No usable receipt. Keep the original request and key.",
    result.response?.status
  )
  process.exitCode = 1
} else {
  console.log(JSON.stringify(result.data, null, 2))
}
```

Run `.venv/bin/python create_connection.py`, `node create-connection.ts` with Node 26 in the TypeScript example project, or `cargo run` in the Rust example project.

A successful `201` returns the permanent `connection.modelConnectionId`, the original operation ID and expiry, the resulting Project Access revision, and four original creator grants. Each initial grant has `canGrant: true` for its exact action on this connection. [Model connection grants](/guides/manage-action-grants#grant-use-of-a-model-connection) lists the actions and the recipients you can choose.

## Check current settings and recorded use

Set `MODEL_CONNECTION_ID` to the returned ID. If you only have the Project ID, list the connections you can inspect by sending GET to the same Project collection URL used for creation. With a current `view-model-connection-configuration` grant, read that connection:

<CodeGroup>

```shell {{ title: "cURL" }}
curl --fail-with-body --silent --show-error --max-time 5 \
  --header @- \
  "$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections/$MODEL_CONNECTION_ID" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

The response reports the saved base URL, selected authentication method and connection settings revision. The `credential` summary shows the current presence and revision. A new connection starts with `credential.present: false` and revision `0`. The [API reference](/api-reference/projects-and-access#list-model-connections) shows how to continue a connection list.

Use the [usage read](/api-reference/projects-and-access#list-model-connection-usage) to see saved Embedding Profiles that select the connection. Append `/usage` to the connection URL and send the same authenticated GET. The response includes only profiles you can currently view. Each item shows the exact model alias and has `null` for both provider observations, `latestAttempt` and `lastValidation`. [Models, processing and search](/product/models-and-search) explains where consumer model and role settings belong.

## Recover an uncertain creation

Keep the original installation, Project, method, route, request body and key. A timeout, disconnect or unusable response can occur after creation. Within the retained period, explicitly repeat the original POST with those inputs and a current credential for the same human. Current `create-model-connections` authority still applies. The receipt describes the original connection and creator assignments. Later changes stay in force. Use GET for current configuration.

If a fresh request rejects the destination, ask the operator to confirm the exact URL and provider selection. Keep the original request separate if you have already sent it and its result is uncertain. Use a new key only for a deliberately changed, reviewed request.

## Save a provider credential

Save the API key for an existing `api-key` connection. The server stores the key without contacting the provider. Use a disposable Project and synthetic token when practicing this procedure.

You need the permanent `PROJECT_ID` and `MODEL_CONNECTION_ID`, a current human bearer credential and `manage-model-connection` on the exact connection. Use your installation's HTTPS URL and the [HTTP setup](/clients/http#call-protected-operations) for `INFRAMELD_URL` and `INFRAMELD_TOKEN`. The ordinary configuration read shows a credential summary under `view-model-connection-configuration`. The dedicated credential read and changes use `manage-model-connection`.

<CodeGroup>

```shell
CREDENTIAL_URL="$INFRAMELD_URL/v1/projects/$PROJECT_ID/model-connections/$MODEL_CONNECTION_ID/credential"

curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --header @- "$CREDENTIAL_URL" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

Read `present` and `revision` in the response. Before the first save, the revision is `0` and `credentialId` and `changedAt` are `null`. Use the revision you read when preparing a save or replacement. [Credential metadata schema](/api-reference/models#ModelConnectionCredentialDetailsResponse).

Create a private request file outside your checkout and choose an idempotency key to identify this save request.

<CodeGroup>

```shell
CREDENTIAL_REQUEST_DIR=$(mktemp -d "${TMPDIR:-/tmp}/inframeld-credential.XXXXXXXX") &&
  CREDENTIAL_REQUEST_FILE="$CREDENTIAL_REQUEST_DIR/credential-save.json" &&
  (umask 077; : > "$CREDENTIAL_REQUEST_FILE") &&
  CREDENTIAL_SAVE_KEY=$(uuidgen)
```

</CodeGroup>

Use a protected local editor or secret-handling tool to prepare `credential-save.json`. Set `expectedCredentialRevision` to the revision you just read as a JSON integer. Set `value` to the raw provider token as a JSON string and omit the `Bearer` prefix. Keep the provider token out of shell arguments, environment variables and logs. Keep shell and HTTP tracing disabled. [Save request schema](/api-reference/models#ModelConnectionCredentialRequest).

<CodeGroup>

```shell
curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --request PUT --header @- \
  --header "Idempotency-Key: $CREDENTIAL_SAVE_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary "@$CREDENTIAL_REQUEST_FILE" "$CREDENTIAL_URL" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

HTTP `200` returns the resulting `credential.revision` and `credential.present`. The receipt's `changed` field records whether the original request changed the slot. To replace a saved key, read the current revision and prepare a separate protected file and idempotency key.

## Recover a save or removal after a lost reply

A timeout or disconnect can happen after the change commits. Keep the original installation, IDs, method, revision and idempotency key. For a save, keep the original JSON file protected as well. Within the retained result period, repeat the original call with a current credential for the same human. Keep the request inputs and key unchanged. Current management permission still applies.

An authorized replay returns the original `credential`, `changed`, `operationId` and `idempotencyExpiresAt` with `replayed: true`. Use GET to find today's state. A different secret under the same idempotency key conflicts. If retention may have expired, inspect current state before deciding whether to send a new request. Once the result is resolved, remove the protected local request file and its directory.

## Remove the saved provider credential

Check the current credential revision again and review any work you know depends on this connection. The usage page shows only the saved Embedding Profiles you can view. An empty page cannot establish that removal has no impact. Future calls that require the key will need a saved credential. Already sent requests may finish. Revoke the provider's own key separately at the provider if needed.

Set `CURRENT_CREDENTIAL_REVISION` to the revision you just read. Run `CREDENTIAL_REMOVE_KEY=$(uuidgen)` once for this removal and keep both values in case the reply is lost.

<CodeGroup>

```shell
curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --proto '=https' --request DELETE --header @- \
  --header "Idempotency-Key: $CREDENTIAL_REMOVE_KEY" \
  "$CREDENTIAL_URL?expectedCredentialRevision=$CURRENT_CREDENTIAL_REVISION" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

HTTP `200` returns the original removal outcome. Removing a present credential advances its revision and returns `credential.present: false`. A removal of an already empty slot at its current revision records `changed: false`. For a lost reply, reuse the original DELETE key and revision. [Recover a save or removal after a lost reply](#recover-a-save-or-removal-after-a-lost-reply).

## Create a processing profile

Save how a Project splits documents into chunks. For example, `support-chunks` uses Docling's hybrid chunking with a limit of 512 content tokens per chunk. Creating the profile saves the definition. The profile keeps that definition for its lifetime. Create a distinct Name to change the settings.

You need the permanent `PROJECT_ID`, a current human credential and `create-processing-profiles` in that Project. Follow [HTTP setup](/clients/http#call-protected-operations) for `INFRAMELD_URL` and `INFRAMELD_TOKEN`. Choose `PROFILE_CREATE_KEY` once for this request, for example by running `PROFILE_CREATE_KEY=$(uuidgen)`.

Save this complete request as `processing-profile.json` in the directory where you will run cURL.

<CodeGroup>

```json
{
  "name": "support-chunks",
  "displayName": "Support chunks",
  "definition": {
    "doclingSlimVersion": "2.148.0",
    "doclingCoreVersion": "2.106.0",
    "assetManifestSha256": "7ea9f3c967a7bc66d2501e466334e7aef46a639e01a11376888321e0f0a51d0e",
    "maxContentTokens": 512,
    "mergePeers": true,
    "repeatTableHeader": true,
    "ocrEnabled": false
  }
}
```

</CodeGroup>

Choose a profile Name of 1 to 63 characters that is unique within the Project. Start with an ASCII lowercase letter, use lowercase letters, digits and hyphens, and end with a letter or digit. Use a display name of 1 to 128 characters.

The Docling versions and asset manifest digest select the supported source. The chunk limit is a whole number from 1 to 1,024 and counts content without tokenizer special tokens. Set `mergePeers` to allow compatible peer chunks to combine within that limit and `repeatTableHeader` to carry the header into chunks from a table. Set both explicitly. Optical character recognition (OCR) is disabled, so set `ocrEnabled` to `false`.

<CodeGroup>

```shell
PROFILE_URL="$INFRAMELD_URL/v1/projects/$PROJECT_ID/processing-profiles"

curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --request POST --header @- \
  --header "Idempotency-Key: $PROFILE_CREATE_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary @processing-profile.json "$PROFILE_URL" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

HTTP `201` returns `profile.processingProfileId`, the original operation ID and expiry, and the resulting Project Access revision. `initialGrants` records the creator's `view-processing-profile` and `use-processing-profile` assignments with `canGrant: true`. Saving defines the settings. Processing documents and checking runtime readiness are separate operations.

## Read or share a processing profile

To read a definition, use the exact `view-processing-profile` permission. Set `PROCESSING_PROFILE_ID` to `profile.processingProfileId` from creation.

<CodeGroup>

```shell
curl --disable --fail-with-body --silent --show-error --max-time 5 \
  --header @- "$PROFILE_URL/$PROCESSING_PROFILE_ID" <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

</CodeGroup>

To list the profiles you can view, send GET to `$PROFILE_URL?limit=25` with the same Authorization header. For another page, pass the unchanged `nextCursor` as `cursor` on the same installation and Project. `nextCursor: null` ends the list. Access is checked on every page. [List processing profiles](/api-reference/processing#list-processing-profiles).

To let Bob inspect this profile, choose `view-processing-profile` and `canGrant: false` on this exact profile. `use-processing-profile` is a separate action for selecting the profile in an authorized operation. Discover Bob under [eligible Project recipients](/api-reference/projects-and-access#find-eligible-project-grant-recipients) with `targetKind=processing-profile`, the permanent profile ID as `targetId` and the exact action. Review the owning Project's Access revision before [setting the assignment](/api-reference/projects-and-access#set-a-processing-profile-action-grant).

## Recover an uncertain profile creation

A lost reply can happen after the profile is saved. Within the retained result period, repeat the POST with the same installation, Project, request and idempotency key. Use a current credential for the same human. The server checks current creation authority and recovers the original `201` receipt. That receipt preserves the original profile, assignments and expiry. Use GET for current access. A changed definition under the same key conflicts. If retention may have expired, inspect current state before sending a new request.

## Copy a processing profile to another Project

Use this manual recipe to copy a saved definition from an authorized GET. Keep the file with your configuration. In `processing-profile.toml`, copy `name` and `displayName` into `metadata.name` and `metadata.display_name`. Copy the seven `definition` values to the corresponding `spec` fields below. Keep the pinned versions, digest, numbers and booleans exactly as returned. This example uses `support-chunks`.

<CodeGroup>

```toml
schema_version = 1
kind = "processing-profile"

[metadata]
name = "support-chunks"
display_name = "Support chunks"

[spec]
docling_slim_version = "2.148.0"
docling_core_version = "2.106.0"
asset_manifest_sha256 = "7ea9f3c967a7bc66d2501e466334e7aef46a639e01a11376888321e0f0a51d0e"
max_content_tokens = 512
merge_peers = true
repeat_table_header = true
ocr_enabled = false
```

</CodeGroup>

Save the following complete script as `convert_profile.py` beside `processing-profile.toml`. Use Python 3.11 or newer. The script checks the file's version and fields, then writes the native creation request to stdout. The creation endpoint validates the setting values.

<CodeGroup>

```python
import json
import tomllib
from pathlib import Path


with Path("processing-profile.toml").open("rb") as source:
    profile = tomllib.load(source)

if set(profile) != {"schema_version", "kind", "metadata", "spec"}:
    raise SystemExit("Use exactly schema_version, kind, metadata and spec.")

version = profile["schema_version"]
if type(version) is not int or version != 1 or profile["kind"] != "processing-profile":
    raise SystemExit("Use a version 1 processing-profile file.")

metadata_fields = {"name": "name", "display_name": "displayName"}
definition_fields = {
    "docling_slim_version": "doclingSlimVersion",
    "docling_core_version": "doclingCoreVersion",
    "asset_manifest_sha256": "assetManifestSha256",
    "max_content_tokens": "maxContentTokens",
    "merge_peers": "mergePeers",
    "repeat_table_header": "repeatTableHeader",
    "ocr_enabled": "ocrEnabled",
}
metadata = profile["metadata"]
spec = profile["spec"]
if not isinstance(metadata, dict) or metadata.keys() != metadata_fields.keys():
    raise SystemExit("Use exactly name and display_name in metadata.")
if not isinstance(spec, dict) or spec.keys() != definition_fields.keys():
    raise SystemExit("Use exactly the seven spec fields shown above.")

request = {field: metadata[key] for key, field in metadata_fields.items()}
request["definition"] = {
    field: spec[key] for key, field in definition_fields.items()
}
print(json.dumps(request, indent=2))
```

</CodeGroup>

Run `python3 convert_profile.py > processing-profile.json`. After it succeeds, set `PROJECT_ID` to the ID of a destination Project where that profile Name is available, then choose a fresh `PROFILE_CREATE_KEY`. Run the [creation POST](#create-a-processing-profile) from the same directory with current create authority in the destination.

Read the newly created profile in the destination. Compare its `name`, `displayName` and every field in `definition` with the source. The destination has its own new `processingProfileId` and its ordinary creator assignments. The file carries only settings and labels. It transfers no existing grants or processing results.

## Create an embedding profile

Save the model and vector settings a Project will use for embeddings. To change those settings later, create a profile with a new Name.

You need a current human credential and `create-embedding-profiles` in the Project. Set `INFRAMELD_URL` and `INFRAMELD_TOKEN` using the [HTTP setup](/clients/http#call-protected-operations), and set `PROJECT_ID` to the permanent Project UUID. Export them so the SDK examples can read them. Generate the create key once for a fresh request and keep it for replay.

```shell
export INFRAMELD_URL INFRAMELD_TOKEN PROJECT_ID
export EMBEDDING_PROFILE_CREATE_KEY="$(uuidgen)"
```

Use a saved Model Connection in the same Project with provider `openai`, base URL `https://api.openai.com/v1`, `apiVersion: null` and `authentication: "api-key"`. Your installation operator must approve that exact URL. The credential slot can be empty because creating a profile makes no provider request. [Create a model connection](#create-the-connection).

Save this request as `embedding-profile.json`. Replace the example connection ID with your connection's permanent ID. The example uses 1,536 dimensions, L2 normalization and cosine distance. Set both prefixes explicitly. Leading and trailing spaces become part of the saved settings. `contextTokens` accepts a whole number from 1 to 8,191. Inframeld records the pinned tokenizer for `text-embedding-3-small`.

<CodeGroup>

```json
{
  "name": "support-embeddings",
  "displayName": "Support embeddings",
  "definition": {
    "modelConnectionId": "00000000-0000-4000-8000-000000000030",
    "model": "text-embedding-3-small",
    "dimensions": 1536,
    "normalization": "l2",
    "distance": "cosine",
    "documentPrefix": "passage: ",
    "queryPrefix": "query: ",
    "contextTokens": 8191
  }
}
```

</CodeGroup>

Run one alternative from the directory containing `embedding-profile.json`. For SDKs, use the [Python](/clients/python#install-from-a-checkout), [TypeScript](/clients/typescript#build-and-install-the-package) or [Rust](/clients/rust#set-up-an-example-project) setup. Save the program as `create_embedding_profile.py`, `create-embedding-profile.ts` or `src/main.rs` in the corresponding example project.

<CodeGroup>

Run `.venv/bin/python create_embedding_profile.py`, `node create-embedding-profile.ts` with Node 26, or `cargo run` in the Rust example project.

HTTP `201` returns the permanent `profile.embeddingProfileId`, the original receipt and expiry, and two creator assignments for View and Use. The layout IDs describe the intended two-shard layout. Creating the profile saves that layout without building an index.

If the response is lost, repeat the original body with the original key while you still have Create authority. During receipt retention, the server returns the original `201` even if the destination is no longer approved or you have lost View on the profile. The recovered receipt describes the original assignments. Changing the body under the same key returns a conflict.

## Read an embedding profile

Set `EMBEDDING_PROFILE_ID` from the receipt. You need current `view-embedding-profile` on the exact profile. A successful GET returns `200` with the saved settings and layout. A missing, hidden or wrong-Project profile returns `404`. [Read request and response](/api-reference/processing#read-an-embedding-profile).

```shell
curl --fail-with-body --silent --show-error --max-time 5 \
  --url "$INFRAMELD_URL/v1/projects/$PROJECT_ID/embedding-profiles/$EMBEDDING_PROFILE_ID" \
  --header @- <<EOF_HEADERS
Authorization: Bearer $INFRAMELD_TOKEN
EOF_HEADERS
```

To list visible profiles, send GET to the collection URL without the profile ID. Use `limit` from 1 to 100, with a default of 25. When `nextCursor` is present, pass it as the `cursor` query parameter on the same Project and installation. Each page checks your current access. [List request and response](/api-reference/processing#list-embedding-profiles).
