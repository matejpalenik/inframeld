# Protect case history and transfer datasets deliberately

Alice exports reviewed Support questions to another installation. The JSONL contains questions, references and source expectations that may reveal private knowledge. Configuration portability cannot silently turn those excerpts into public data or admitted corpus documents.

## Authority and audiences

Evaluation uses six separate exact-Pipeline use permissions. Eligible humans and applications can receive those grants. Grant/audience administration remains human-only. Exact creator assignments and the separate `manage-evaluation-case-audiences` capability are accepted. Public/physical schemas and runtime qualification remain distinct delivery work.

A human approves the Pipeline's import audience. Applications import into that saved current audience. Changing the default affects future imports only. Existing-case audience changes require separate explicit review and management of every authoritative old/new group. Current source/audience checks apply to protected reads, previews, snapshots, results and exports.

## Follow dataset transfer

1. Transfer questions, references and expectations explicitly as protected versioned JSONL. Ordinary configuration definitions use TOML. Configuration import does not imply dataset import or evaluation.
2. Resolve destination resource identities and deliberate audiences. Unresolved content must have a reviewed audience before linking. Imported provenance cannot grant permission or replace verified source proof.
3. Reuse exact identity for unchanged reimports. New or changed cases become unreviewed.
4. Eligible applications may accept exact revisions only with explicit current authority. Review never silently follows generation or import.
5. Preserve fixed benchmark membership and historical revisions. Do not substitute newer sources, reduce a benchmark silently or start evaluation without an explicit operation.

## Changes, erasure and comparability

Current access protects captured settings, cases, results and reconstructible evidence. Erasure applies to derived questions/references as well as source text. Source replacement does not retarget old expectations. Missing dependencies make the retained input unavailable or its mapping unscorable under the owning contract.

Retained snapshots permit fresh execution rather than historical-score reuse. Reference answers never enter Pipeline execution or supply extra faithfulness support. Query provenance, Evaluation evidence and production traces have different retention and permission rules. No record type becomes a hidden content archive.

Historical OpenEvals results retain their original definitions. Fresh comparisons execute both sides with one benchmark/evaluator and show missing pairs. Manual release mode controls serving selection but does not freeze current shared connections. Offline scores never pause Automatic updates or authorize release.

## Status and sources

These are accepted protection and transfer rules. Exact routes, storage schemas, delivery behavior and runtime qualification remain recorded separately. Manual blank-form case authoring and additional export/judge presets remain deferred.
