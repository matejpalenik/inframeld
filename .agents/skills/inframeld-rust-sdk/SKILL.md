# Inframeld Rust SDK

Help a developer consume and maintain the Rust client generated by `openapi-to-rust` with the repository's pinned source patches. [ADR-0088](../../../docs/adr/ADR-0088-use-a-pinned-patched-generator-for-the-rust-sdk.md) selects this approach. This skill owns Rust-specific behavior and maintenance. The [SDK skill](../inframeld-sdks/SKILL.md) owns shared generator policy and qualification, while Application Contracts retains HTTP semantics and compatibility policy.

## Working model

Alice reads her current session through the SDK. The selected generated `get_current_session` operation returns `response::ApiResponse<T>`: its `body` is the generated session model, while `status` and `headers` belong to that same response. She can correlate a request ID without sending another request. An HTTP failure remains an error with its available typed problem, status, headers and raw body. A timeout cannot establish whether a write completed.

The [generated client](../../../packages/sdk-rust/generated/client.rs) owns implemented signatures. Inspect it before proposing a call. Keep generated models and methods in the SDK crate rather than copying their shapes into the CLI. Local Cargo path dependencies need no registry publication.

## Essential constraints

- Generate the complete Rust application client from the authoritative native OpenAPI contract. Patch generator source when needed. Do not edit generated Rust, weaken backend schemas or substitute handwritten HTTP methods to make qualification pass.
- Read current tool versions from [version configuration](../../../packages/sdk-tools/generators/manifest.json), source identity and patch order from the [patch manifest](../../../packages/sdk-tools/generators/manifest.json), and selected options from the [patched configuration](../../../packages/sdk-tools/generators/rust.toml). Do not turn this skill into another pin or patch inventory.
- Keep generation an explicit development action. Ordinary SDK builds consume included source without running a generator or backend. Use the unpublished `inframeld-sdk` crate selected for active work. Retain `publish = false` until separate release work changes it.
- Use caller-supplied base URLs and credentials with the configured timeout, currently five seconds, disabled automatic redirects/retries and selected tracing. `new`/`Default` apply that policy. `with_client` preserves caller-supplied transport settings, including deliberate overrides. Preserve typed failures and available response metadata. An acknowledgment or decode failure must not cause another dispatch.
- Keep qualification faithful. Drivers expose SDK observations rather than repairing serialization, reconstructing metadata or implementing missing operations. Synthetic capability fixtures do not establish product workflow support.

## Explain or change

For a question, inspect and explain. Loading this skill grants no edit, publication or external-action authority. Repository code planning, suggestions and changes require [Coding Standards](../inframeld-coding-standards/SKILL.md), plus [Rust Standards](../inframeld-rust-standards/SKILL.md), without applying backend Python declarations. Generated sources remain generator-owned.

For ordinary SDK consumption, read only the relevant generated model/method and its native contract. Keep login orchestration, credential storage and command presentation with their existing owners. Load Application Contracts when HTTP behavior or retry meaning is affected, rather than importing backend domain rules into the SDK.

For generation changes, qualification work, a defect, a generator upgrade or patch retirement, read [Rust maintenance](references/generator-maintenance.md) and the applicable [shared maintenance policy](../inframeld-sdks/references/generator-maintenance.md). Ordinary consumption needs neither the other languages' skills nor the whole shared strategy. Keep routine command invocation and cache mechanics in the existing runbooks below.
