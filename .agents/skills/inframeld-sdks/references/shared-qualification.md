# Qualify every SDK against shared HTTP scenarios

Alice adds an operation with an optional nullable description. A common case describes omission, explicit null and a value. Each SDK constructs its generated model and calls its generated operation. The backend records what arrived, while the shared oracle checks the native result. Agreement between SDKs alone could let the same defect pass everywhere.

[ADR-0090](../../../../docs/adr/ADR-0090-qualify-sdks-with-shared-contract-scenarios.md) accepts the strategy. [ADR-0091](../../../../docs/adr/ADR-0091-promote-selected-sdks-and-retire-generator-comparisons.md) promotes its implementation and retires comparisons. This reference owns conformance policy. The [runbook](../../../../packages/sdk-tools/README.md) owns commands, caches and environment mechanics.

## Current implementation and accepted target

The [test workflow](../../../../packages/sdk-tools/src/workflows/test.ts) runs ordinary [feature tests](../../../../packages/sdk-tools/tests/conformance) through Node's runner for Rust, TypeScript Node/Chromium and Python sync/async. Inputs and assertions live together. A small registration helper records identity/operation metadata without request-building or assertion switches. [ADR-0092](../../../../docs/adr/ADR-0092-maintain-sdks-with-typed-workflows-and-native-conformance-tests.md) records this organization. Production clients stay in language packages. Fixture clients and native drivers stay in private tooling outside distributions.

[Automatic CI](../../../../.github/workflows/sdk-conformance.yml) runs Linux for SDK/API-affecting changes, with macOS for generator/patch/configuration and platform-sensitive process/browser/lifecycle changes, plus manual qualification. Its aggregate inspects required job results and [complete artifacts](../../../../packages/sdk-tools/src/ci/evidence.ts). Requiring that aggregate in GitHub branch rules is a separate external configuration step. Implemented automation is not evidence that Linux or remote macOS has executed.

## Shared expectations, native calls

OpenAPI supplies operation identity and shapes. The owning workflow and inspected backend supply business expectations. A case calls a public SDK operation through its language driver and exposes explicit native success/failure, validation provenance and available body/status, headers, raw content and cause. HTTP 200 cannot override a decoding failure. Native Rust/Python drivers exchange one versioned JSON request/result on stdin/stdout. Protocol, identity and call inventories are validated. A driver crash is distinct from an expected SDK failure.

Drivers cannot repair serialization, fill absent fields, fabricate metadata, create replacement typed error models, issue fallback HTTP calls or repeat work to recover missing information. Native model serialization can normalize observations, but must preserve omission/null, scalar types and header meaning. TypeScript's other response modes remain unqualified. Python's sync bridge retains its actual lifecycle. Browser Origin, cookies and opaque redirects use real platform behavior rather than invented metadata.

The [controlled backend factory](../../../../apps/backend/tests/support/sdk_conformance_app.py) runs production routers with synthetic authentication/application collaborators and shared FastAPI schema fixtures. Each profile gets fresh fixture state. Cases explicitly register their call identities, retrieve only their evidence and delete it after collection. The independent total-request counter survives case deletion and exposes redispatch without the witness header. Browser contexts isolate cookies between scenarios. Faults are arranged explicitly through private control endpoints rather than inferred from scenario names. Witnesses record dispatched method/path, encoding, explicit null/absence, exact uploaded bytes/filename and operation counts independently of SDK results.

## Coverage and completeness gates

The [coverage gate](../../../../packages/sdk-tools/src/conformance/coverage.ts) inventories native production and fixture operations and requires meaningful success scenarios and bindings for every selected SDK. Unknown operations, duplicate scenarios and missing bindings fail. Cases must invoke their declared operation and calls must reach its method/path exactly once. Success assertions check the exact expected HTTP status and meaningful input fields. Required/optional/null and boolean-constant regressions include native model and malformed-response checks. An advertised binding that invokes the wrong method fails behavior, while missing generated methods fail compilation or invocation.

Expected failure and business cases still need review. Changing an existing operation's fields requires reviewing its cases even if its ID remains unchanged. The gate establishes coverage inventory, not exhaustive business correctness.

Every expected runtime and named HTTP scenario must occur exactly once. Missing, duplicate, skipped, unavailable or unexpected results cannot produce a green verdict. Clients and stages execute independently, and other SDKs still run after one fails. Separate generation, compilation, native driver typing/model regressions, HTTP behavior, drift, generator regressions, archives and clean external consumption. Archive building does not depend on executing conformance. Installed consumers make actual public SDK requests, inspect typed results/failures and close used Python pools on the matching lifecycle. Native Rust/TypeScript/Python checks need not have identical mechanics or counts. Filtered local runs are marked partial and cannot satisfy complete CI verification. Client-reuse sequences retain one transport/client pool across calls. Resource deadlines, interruption and cleanup failures are part of verification, not optional warnings. Startup owns resources before returning a fixture. Profile cancellation closes case contexts and owned browser/backend resources, with forced browser termination after failed graceful cleanup. See the runbook for budgets and development overrides.

Keep native request validation separate from a case specifically exercising a server-side typed error. Such a case may deliberately use a generated model's native unchecked-construction API to send invalid input. Normal model validation still needs its own native checks. This exception does not permit repairing valid requests or inventing missing generated operations.

## Endpoint delivery and failure investigation

For authorized delivery, follow the [endpoint walkthrough](../../../../packages/sdk-tools/docs/adding-endpoint.md): inspect and test backend behavior, update native OpenAPI, add shared cases/native bindings and regenerate explicitly. Run the permanent verification command. For new harness or generator behavior, use Coding Standards' scaffold-first TDD and observe the intended regression before fixing it. Keep that regression after patch retirement.

Cases preserve bearer/cookie alternatives, CSRF/Origin, required/optional/null fields, scalar unions, enums/UUIDs, typed Problem Details, request IDs/challenges, query/body/header encoding, multipart content, explicit pagination, timeouts and lost acknowledgments. A lost response cannot authorize redispatch. Unexpected or malformed bodies remain failures with available context. Retain negative required-object/null/empty, malformed container/error bodies, swapped status/media schemas, undeclared-success, primitive-type and invalid-UTF-8 cases alongside legitimate nullable and bodyless responses, including their coexistence with class/default variants. Native constructor/deadline/redirect tests complement drivers that deliberately configure transports for shared cases. Synthetic fixtures establish capabilities rather than delivery of new product workflows. Body absence differs from null. A generated decoder, generated schema validator, plain JSON parser and no validation are distinct observations, and a driver must not revalidate an HTTP model to conceal SDK success.

Investigate stale generation, missing bindings, fixture/backend mismatch and generator defects separately. A red result is not automatic permission to patch the generator or weaken an assertion. [Common maintenance](generator-maintenance.md) owns provenance, source fixes, upgrades and retirement.

This suite proves SDK and HTTP-adapter behavior. It does not replace domain/service tests, demonstrate PostgreSQL atomicity with doubles or qualify real identity providers. Rust-only synthetic binary/streaming/SSE evidence is not product workflow qualification or inherited by other languages. Jobs, receipts, unsupported protocols and complete CLI/account-UI journeys remain separate work. Use [Testing](../../inframeld-testing/SKILL.md) for broader evidence boundaries.

[ADR-0093](../../../../docs/adr/ADR-0093-preserve-response-integrity-and-type-native-sdk-boundaries.md) records response integrity, headers and typed boundaries. The [hardening report](../../../../docs/development/reports/sdk-hardening-verification.md) records checks actually executed. Applicable CI and independent review are required before a 9/10 qualification or issue-closure claim.

[ADR-0094](../../../../docs/adr/ADR-0094-select-sdk-response-variants-and-safe-transport-defaults.md) and the [response-fix review](../../../../docs/development/reports/sdk-response-fixes-verification.md) supplement this evidence. Architectural review excluding CI evidence does not claim unexecuted platform qualification.
