# Inframeld Pipelines and Releases

Explain one user workflow while keeping two owners clear. Pipelines owns immutable configuration, builds, query orchestration, receipts, and feedback. Releases owns Deployment serving pointers, cohorts, publication modes, and transitions.

## Essential boundaries

Query on a Pipeline executes that Pipeline's working settings. There is no Experiment resource. Query on a Deployment instead uses its serving selection. Humans and applications may receive explicit grants on either exact resource, but neither grant includes the other. Query-trace inspection needs its own grant on the corresponding resource and current source access, including when inspecting another caller's answer. Query permission alone does not grant inspection. Follow [Access](../../../docs/development/access-control.md#pipeline-query-authority). Captured inputs record what an operation used, not another resource lifecycle.

For delivery, read [CLI-first ownership](../../../docs/development/cli-delivery-plan.md) and [ADR-0055](../../../docs/adr/ADR-0055-deliver-cli-first-v1-through-openapi-generated-clients.md). Full Studio is deferred; the small Ory account UI is required independently. Direct `query --pipeline` selects direct Pipeline querying and `query --deployment` live serving. [ADR-0056](../../../docs/adr/ADR-0056-support-explicit-local-hosted-or-disabled-reranking.md) adds explicit hosted reranking and selects Ettin 32M locally while preserving bounded candidate identity. [Reranking/context](../../../docs/development/pipelines-and-releases.md#reranking) owns whole-passage fitting. Preserve only planned hook interfaces, not executable hooks. Configuration export excludes Deployments and versions; see [portability](../../../docs/development/configuration-portability.md).

For the optional post-setup evaluation branch, follow [generation and review](../../../docs/development/evaluation.md#generation), [fresh execution](../../../docs/development/evaluation.md#comparison), and [CLI starter-evaluation journey](https://github.com/matejpalenik/inframeld/issues/179). Finish is the default completion action; no generator or judge is required for a useful pipeline. Ragas runs through the existing gateway under [ADR-0051](../../../docs/adr/ADR-0051-use-ragas-for-generated-tests-and-faithfulness-evaluation.md). Evaluation executes ordinary queries without supplying reference answers/expected evidence. Choosing generator/judge connections does not change the pipeline's settings. Neither review nor comparison starts publication or changes mode.

Shared connection administration can change current model access without Build or publication, even in Manual mode. Connection managers own that reviewed live authority, not ordinary Pipeline editors. Pipeline rollback does not restore access settings or credentials. Use another connection selected on the working Pipeline for an isolated query/build/release migration. Reject incompatible or unproven shared embedding changes before mutation. Captured operations observe access revisions and stop remaining model dispatch after relevant changes rather than continuing against old access settings; credential-only rotation remains independent.

A Pipeline has one saved working configuration with immutable revision history. Save/restore creates a new current revision; temporary overrides do not save it. An execution-input snapshot captures exact effective settings/corpus and complete verified bindings before question execution, without creating a release-ready version. A PipelineVersion is a successful release-build result. A reserved build identity is not yet serveable. A Deployment selects ready versions through current/candidate/previous pointers, never a mutable working copy. An AnswerReceipt records live serving; direct-query/evaluation stay outside production feedback. Do not infer a table or class per concept.

Direct querying shares ordinary pipeline execution, Indexing preparation and ModelGateway; it is not a second service or live Deployment. Prompt/reranker changes can reuse verified data; changed chunking/embedding/corpus may require disclosed paid preparation. Current access, health, limits and pins still apply. Captured inputs stay fixed through all evaluation cases. Protected inspection and trace policy remain separate; production Query grants and snapshot IDs do not grant Pipeline Query access.

The CLI Build workflow captures current saved configuration and corpus, not an evaluation run or unsaved overrides. Select the sole live Deployment or require a choice when there are several; never fan out. With none, ordinary Build leaves an unpublished version, while existing first-publication onboarding keeps its separate authority. Manual leaves ready output; Automatic coordinates preparation and separate conditional publication under captured/current permissions. No separate CLI apply command is required. Display mismatched evaluation inputs as evidence limits, not a mandatory evaluation gate.

The underlying build operation publishes complete ready bindings after Indexing verification; it never moves traffic alone. Live queries select one version with a bounded retention pin; direct querying uses fixed captured working-configuration inputs with the same execution protections. Current authorization and health are checked before egress and disclosure. Mid-query Pipeline edits/releases do not silently reroute work; relevant shared access changes follow the stop-before-further-dispatch rule, with actual attribution for already-sent calls. ModelGateway handles embeddings and generation. Failed required shards, credentials, or reranking do not justify a different provider or unfiltered fallback.

Its caller supplies the exact authorized saved configuration/corpus: current working for explicit CLI Build, Deployment-selected for document-triggered work. Do not make the common build re-resolve current working settings. Re-enabling Automatic initially reviews the currently serving version's configuration, not a stale automatic binding; any different saved selection is explicit.

Canary affinity controls cohorts, not identity or permissions. Stable principal and rollout identities participate in assignment; rotating a key or changing percentage must not reshuffle callers. Ten percent is a share of identities, not an exact request count. Aborting B preserves current A and previous Z; promoting B makes A previous. Rollback consumes its one-step target and is blocked by an attached candidate or unusable target. Do not choose another target silently.

Manage releases is one action per Deployment covering publication, candidate/canary control, rollback, mode switches, and automatic input selection. It replaces earlier Publish/deploy wording. Delete, Build, document access, and non-serving Edit configuration remain separate. Human creation uses project Create Deployment and atomically records the ready initial version, Deployment, and explicit creator grants. Creator history never overrides later grant removal.

Private starter provisioning explicitly records the creator as both ordinary member and manager of its group under the [Access rule](../../../docs/development/access-control.md#group-managers). This does not replace separate build or release grants.

The default path starts Automatic updates; explicit new deployments default Manual releases with an automatic option. Mode belongs to the Deployment, not every deployment of a Pipeline. Before first publication, the default binding holds its mode/control revision and remains not-ready; no fake version is created. First publication transfers this state atomically.

Separate synthetic model preflight is optional. Complete configuration and a genuinely ready version with verified materializations may reach first publication while generation is still untested. Real model calls retain every security and response check and automatically record validation only for the actual role/model/configuration and connection/credential revisions used. Historical success is not release authority, index readiness or current provider health. Missing required credentials or invalid embeddings still fail; a stale or absent validation marker alone does not block use. Credential rotation makes old evidence inapplicable without requiring a fresh synthetic call.

Automatic updates uses complete authorized live-input batches or an explicit policy-controlled CLI Build, then readiness-only preparation and separate conditional publication. Require relevant mutation/input rights, Pipeline Build, and target Manage releases; before the default Deployment exists, authorized onboarding instead needs project Create Deployment. Source updates use the Deployment's selected configuration, not the evolving working copy. Development-only documents stay outside live-watched collections. Edits, restores, direct Pipeline queries and evaluation never publish or supersede pending publication. Recheck current authority before dispatch and publication. A competing creation cannot authorize an update to someone else's existing target. Failure keeps healthy current.

Automatic → manual invalidates pending publication while allowing useful builds to finish. Manual → automatic freezes selected inputs and admits fresh work; even a 0% attached candidate blocks the switch. Every switch advances the control revision, so off/on cannot revive an old job. Newest authorized request identity and current attempt/serving state guard publication. Superseded work cannot become a fallback after a newer failure. Canaries and rollback require manual mode; scores and feedback never authorize releases.

Receipts retain exact attribution and every final source, including uncited evidence. Lost-answer replay is receipt-only, not regeneration. Feedback permits one current editable rating per answer/originating principal, with current access, revisions, and retention. Late feedback stays on the original version/cohort. Coverage uses eligible produced receipts in the same authorized answer-time window; missing ratings are not negative votes and an application is not a verified human audience.

[CLI feedback capability](https://github.com/matejpalenik/inframeld/issues/191) puts authorized feedback reporting and own-live-answer rating/correction in CLI v1, using the ordinary backend contracts. Reporting cannot authorize editing others' ratings, recover answer text from receipts or include direct-query/evaluation statistics. Follow [feedback reporting](../../../docs/development/answer-feedback.md#reporting) for coverage and client behavior; backend and CLI qualification must both remain in the release dependency chain without Studio.
