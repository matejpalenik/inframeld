# Architecture decision records

Start with [Understanding Inframeld](../ARCHITECTURE.md), then use the topic guides for current behavior and [data-model.md](../../.agents/skills/inframeld-architecture/references/resource-names-and-identity.md) for record definitions. Each ADR explains one architectural choice, its context, alternatives, outcome, and consequences.

## Authority and qualification

Accepted design is separate from tested implementation. The product is a single-server, Apache-2.0 Docker Compose deployment with strict DDD/Clean Architecture and lightweight CQRS. Immutable vector generations, PostgreSQL membership, server-owned permission filters, SeaweedFS, Kratos/deployment OIDC, Hydra for human CLI OAuth, opaque fixed-integration credentials, group allowlists, custom/private model endpoints and the universal ModelGateway boundary are selected.

Embedded Ragas is selected for optional starter generation and claim-based faithfulness under [ADR-0051](ADR-0051-use-ragas-for-generated-tests-and-faithfulness-evaluation.md), superseding OpenEvals. Generator and judge connections are explicitly selected, with no mandatory model. Reviewed case revisions, frozen benchmarks, fresh comparisons, and protected history remain application-owned. Source-inspected compatibility still needs runtime qualification. [ADR-0052](ADR-0052-separate-experimental-execution-from-release-ready-pipeline-builds.md) adds Edit → Query/Evaluate → Build of saved configuration, followed by policy-controlled publication. Manual release retains optional post-build comparison, canary, promotion/rejection and rollback. Automatic updates uses advance authorization from a live-input source operation or explicit policy-controlled Build, never evaluation scores or working edits. Work and routing run automatically after admission. GitHub/external runners, webhooks and a workflow engine are deferred.

The detailed feedback PUT/GET/editing contract and two-tool MCP/header-capable trusted-client profile are **accepted**, with interoperability tests pending. Native FastAPI OpenAPI **3.1.x** is accepted; there is no 3.0.3 output requirement. [ADR-0055](ADR-0055-deliver-cli-first-v1-through-openapi-generated-clients.md) selects CLI-first v1 with the required small Ory account UI, generator-neutral application clients and deferred Studio. Backend work proceeds independently, and future Studio follows the same accepted CLI-led behavior.

Default configure-models → upload → ask and persistent application-entered credentials are confirmed v1 requirements. Private starter/access defaults are accepted in ADR-0046 and its guide, and ADR-0048 selects application-managed authenticated ciphertext in PostgreSQL using PyNaCl with a separate persistent root key. The first-answer scenario is accepted as a flexible usability goal: two minutes is aspirational and roughly ten minutes is also acceptable, with no hard timing gate. Reversible Automatic updates / Manual releases are accepted. The default path starts automatic; newly created deployments default manual with an explicit automatic option. Authorized updates can build and publish repeatedly, while manual canaries and release decisions remain explicit. There is no one-time Prepare and ask operation. Precise default-selector shapes remain implementation recommendations, not backend approval blockers.

Backup/restore remains required with the existing provisional coordinated baseline; numerical objectives and validation are deferred to implementation. Index reconstruction, third-party OAuth/MCP onboarding, verified user delegation, general ACLs, LangSmith/Langfuse/exporters and deeper evaluation diagnosis remain deferred. Inframeld-owned OAuth issuance is not selected: [ADR-0053](ADR-0053-use-kratos-and-hydra-for-human-cli-authentication.md) uses Hydra for the first-party human CLI and retains Kratos identity, private introspection and current Access checks. Application keys and the limited MCP client profile remain separate. Exact image pins, identity integration, parser enforcement, gateway integration, model calibration, vector recovery and capacity still need tests; none has been certified by this documentation work.

Model preflight is optional under [ADR-0050](ADR-0050-make-model-preflight-optional-and-record-runtime-validation.md). A successful real model call can establish revision-specific validation evidence after response checks, without another synthetic request. A validated-model marker is not a first-publication prerequisite. Runtime security, configuration, response and index-readiness checks remain mandatory.

[ADR-0054](ADR-0054-use-shared-current-model-connections.md) selects one current access configuration per connection. Connection managers may approve guarded shared live updates; prepared/in-progress embedding incompatibility or unknown compatibility rejects activation. Pipeline/model settings and vector history remain immutable, while actual executions record current connectivity. Publication modes do not shield shared infrastructure changes.

Historical hosted filenames do not imply a mandatory AWS architecture. The current ADR filenames describe the single-server deployment and recovery choices.

The wording above preserves the available scope and qualification statements from the earlier index. These are accepted design and pending qualification, not a claim that all features work today. The former closing review is [unavailable](../development/documentation-maintenance.md#unavailable-historical-material); it is not a new gate.

## Decision index

The index contains 79 records. ADR-0001 through ADR-0048 retain the numbering established during the editorial rewrite. ADR-0049 requires ordinary membership for every group manager, partially superseding ADR-0014. ADR-0050 makes model preflight optional and records validation through successful real use, partially superseding ADR-0025. ADR-0051 selects Ragas for generated tests and faithfulness, superseding ADR-0030. ADR-0052 adds direct Pipeline queries before release builds (the historical terminology does not introduce an Experiment resource), partially superseding ADR-0031's ready-version-only inputs and ADR-0047's configuration-update interaction. ADR-0053 adds Hydra for first-party human CLI authentication, partially superseding ADR-0012's earlier browser-focused deferral. ADR-0054 selects shared current connections with guarded updates, partially superseding ADR-0025's connection pinning and ADR-0008's access-configuration freeze. ADR-0055 selects CLI-first v1 and partially supersedes ADR-0006's external tooling prerequisite. ADR-0056 records explicit local/hosted/none reranking, partially superseding ADR-0042. ADR-0057 replaces the earlier seven-action project-creator seed with eleven explicit reviewed grants. ADR-0058 clarifies temporary product blocking during identity-recovery cleanup while retaining deliberate suspension restoration. ADR-0059 supersedes ADR-0057 with seventeen Project creator grants and fixed resource assignments. ADR-0060 retains human-only resource provisioning in v1. ADR-0061 controls Evaluation audiences through Pipeline authority. ADR-0062 selects current-authority invitation activation. ADR-0063 defers product non-query diagnostic browsing. ADR-0064 centralizes principal eligibility while retaining focused lifecycle aggregates. ADR-0065 places complete write transactions in application services. ADR-0066 selects typed operation contexts and explicit Command classification. ADR-0067 standardizes authorization capabilities with typed requests. ADR-0068 models project grants through membership aggregates and partially supersedes ADR-0065's writer boundary while retaining application-owned transactions. ADR-0069 releases completed recovery obligations independently, including before local admission. ADR-0070 selects bulk Hydra recovery cleanup and accepts delayed-attempt effects on newer CLI credentials. Filenames describe focused decisions, and existing IDs remain stable.

## Maintaining these records

Use the [ADR template](template.md) and [documentation-maintenance guide](../development/documentation-maintenance.md). Keep current IDs stable; a changed architectural choice receives a new superseding record. Ordinary corrections and navigation improvements may amend an existing record.

The nine [skill reading routes](../development/guides/skill-authoring.md#skill-reading-routes) lead to current guides. Documentation work does not authorize paid trials, code changes or migrations. Markdown and link checks establish editorial integrity, not runtime behavior. The [delivery plan](../../.agents/skills/inframeld-architecture/references/v1-scope-and-extension-boundaries.md) tracks implementation and qualification separately.

Pending analyses are discoverable through [the existing module map](../../.agents/skills/inframeld-architecture/references/module-map.md#pending-decision-navigation). They reserve no ADR numbers and do not change accepted decisions. Resolve relevant choices through [the just-in-time approval and consistency workflow](../development/guides/architecture-decisions.md#just-in-time-architecture-decisions).

For contributor routes, start with [developer documentation](../development/README.md). Detailed behavior has one owning skill reference. Older GitHub issue paths may refer to removed historical guides.

- [ADR-0080: Limit product deletion status to the initiating human](ADR-0080-limit-product-deletion-status-to-the-initiating-human.md). Accepted status-viewer scope. Other retention choices remain pending.
